# Android (Play Store) packaging

Tandu is shipped to the Play Store as a **Trusted Web Activity (TWA)** — a thin
native shell that opens the live `tandu.app` PWA full-screen in Chrome's engine.
No app logic lives here; the wrapper just points at the deployed site. Updating
the web app (via `./deploy.sh`) updates what users see instantly. You only build
a new `.aab` when native config changes (name, icon, version, signing).

The tooling is Scala, run with [scala-cli](https://scala-cli.virtuslab.org) — see
`tooling/`.

## Files

| File | Committed | Purpose |
|------|-----------|---------|
| `twa-manifest.json` | ✅ | Source of truth for the wrapper (package id, colors, icon, version). |
| `tooling/` | ✅ | scala-cli project: `packageAndroid` + `verifyAndroid`. |
| `play-app-signing-fingerprints.txt` | ✅ (after first upload) | Extra SHA-256s to trust — notably the Play "App signing key". |
| `android-upload.keystore` | ❌ (gitignored) | Your upload signing key. **Back it up.** |
| `keystore.env` | ❌ (gitignored) | Keystore passwords. **Back it up.** |
| `app/`, `gradle/`, etc. | ❌ (gitignored) | Regenerated by `bubblewrap update`. |

## Workflow

```sh
scala-cli run android/tooling -M packageAndroid   # build .aab + regenerate assetlinks.json
./deploy.sh                                        # publish assetlinks.json to tandu.app (Cloudflare)
scala-cli run android/tooling -M verifyAndroid     # confirm the web <-> app association is live
```

First `packageAndroid` run is interactive **once**: Bubblewrap downloads its own
JDK 17 + Android SDK (answer "Yes"). Later runs are non-interactive.

`bubblewrap update` auto-increments `appVersionCode` in `twa-manifest.json` on
every build, so each build is a higher, never-duplicate Play `versionCode`
(Play rejects duplicates). `versionName` is stamped from `package.json`. Commit
the bumped `twa-manifest.json` to keep the counter monotonic across machines.

## The Play App Signing gotcha

By default Play re-signs your upload with **Google's own** app-signing key, so
the certificate users actually install with is **not** your upload key. After the
first upload:

1. Play Console → Test and release → App integrity → **App signing key
   certificate** → copy the **SHA-256**.
2. Paste it into `play-app-signing-fingerprints.txt` (one fingerprint per line).
3. Re-run `scala-cli run android/tooling -M packageAndroid` (regenerates
   `assetlinks.json` with both keys) and `./deploy.sh`.

Until that key is in `assetlinks.json`, installed builds show a browser address
bar instead of launching full-screen.

## Local device test

```sh
adb install android/app-release-signed.apk
```

(`adb` ships with the Android SDK Bubblewrap installed under `~/.bubblewrap`.)
